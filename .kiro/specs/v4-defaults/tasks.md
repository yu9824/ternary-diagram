# Implementation Plan

タスク 1〜4 は予告の段（v3.4.0）、タスク 5〜8 は切り替えの段（v4.0.0）。切り替えの段は、予告の段を main にマージして v3.4.0 のタグを打った後に着手する（design.md の Migration Strategy）。

## 予告の段（v3.4.0）

- [x] 1. 位置引数の予告の仕組み
  - 位置引数で渡されたオプションの名前を、引数の並び・データの引数の数・渡された位置引数の数から求める純粋な関数を作る。データの数以下なら空を返す
  - 予告の文面（渡された引数の名前、4.0.0 ではキーワードで渡す必要があること、キーワードで渡した書き方の例）を作る関数を作る
  - メソッドを包み、オプションが位置引数で渡されたら利用者の行を発生位置にして FutureWarning を出し、元のメソッドを同じ引数で呼ぶデコレータを作る。1 回化の判定を外から受け取れるようにし、受け取らなければ毎回出す
  - 包んだメソッドの引数の並び・docstring が元のものと同じになる
  - 単体テストで、名前の求め方、文面の要素、元の関数の戻り値がそのまま返ること、1 回化の判定が偽なら警告しないこと、引数の並びと docstring が引き継がれることを確かめ、すべて通る
  - _Boundary: deprecate_positional ほか_
  - _Requirements: 1.2, 1.3, 1.4, 1.5, 1.6, 1.7_

- [ ] 2. 公開メソッドへの位置引数の予告の適用
- [x] 2.1 4 つの公開メソッドに予告を付ける
  - `TernaryDiagram` の作成（データは `materials`）、`scatter` と `contour`（データは `vector`・`z`）、`colorbar`（データは `mappable`）に予告を付ける。作成は呼ぶたびに、ほかの 3 つは三角図ごと・メソッドごとに 1 回だけ出す
  - 引数の型と既定値、パッケージ内の呼び出しは変えない
  - 新しい結合テストのファイルで、4 メソッドについて次を確かめ、すべて通る: 位置引数で渡すと引数の名前を含む FutureWarning が出て、発生位置がテストファイルになる。結果（座標・色・levels・カラーバーの有無）が同じ値をキーワードで渡したときと同じになる。同じ三角図で 2 回呼んでも警告は 1 回で、別の三角図ではまた出る。キーワードだけで渡したとき、データだけを位置引数で渡したときは警告しない
  - 6 番目の位置引数（`colorbar`）を確かめる既存のテストで、位置引数の予告の警告を受け取るようにする。テスト一式が `-W error::FutureWarning` で通る
  - 共通の doctest のランナーと docstring の静的テストが、4 つのメソッドを今までどおり集めて通る
  - _Depends: 1_
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5, 1.6, 1.7, 8.1, 8.3_

- [ ] 2.2 予告を docstring に書く
  - `scatter`・`contour`・`colorbar` の説明に、データの後の引数を位置引数で渡すのは 3.4.0 から非推奨で 4.0.0 でキーワード専用になることを書く。`TernaryDiagram` は `ax` と `auto_latex_notation` の項目に書く
  - クラスの docstring の縦横比の説明に、4.0.0 で Axes の枠を三角形に合わせて縮める方法に変わることを書く
  - docstring の例はキーワードで渡す書き方のままで、共通の doctest のランナーが FutureWarning を出さずに通る。docstring の静的テストが通る
  - _Requirements: 9.5_

- [ ] 3. (P) 縦横比の v3.4.0 での挙動を固定するテスト
  - 既定の縦横比の固定方法が、データの範囲を広げる方法（`datalim`）のままであることを確かめる
  - 作成後に利用者が `adjustable="box"` に変えた設定が、`scatter`・`contour`・グリッドの描き直しの後も保たれることを確かめる
  - 追加したテストが、ライブラリのコードを変えずに通る
  - _Boundary: 縦横比の設定_
  - _Requirements: 7.4, 7.5_

- [ ] 4. 予告の段の文書と検証
- [ ] 4.1 CHANGELOG と移行ページに予告を書く
  - CHANGELOG の Unreleased の Deprecations に、位置引数の非推奨（対象の 15 の引数の一覧）と、4.0.0 での縦横比の固定方法の変更（影響: 凡例の `loc` の位置、自動で付くカラーバーの長さ）を書く
  - 移行ページに、位置引数の節（影響のある書き方、キーワードで渡す書き方）と、縦横比の節（影響、v3.x のうちに作成後の `set_aspect` で `adjustable="box"` にして試す方法）を足し、概要の表と「影響を受けるコードの探し方」に加える。ページ間のリンクには明示のターゲットを置く
  - ドキュメントを CI と同じ手順でビルドし、警告 0 件で、移行ページの実行されるセルが FutureWarning を stderr に出さない
  - _Depends: 2.1_
  - _Requirements: 9.1, 9.2, 8.3_

- [ ] 4.2 予告の段の全体の検証
  - テスト一式（`-W error::FutureWarning`）、`mypy src`、`ruff check` と `ruff format --check`、ドキュメントのビルドを実行し、すべてエラー・警告 0 件で通る
  - 既存の描画のテスト（座標・色・zorder・カラーバー・レイアウト）と、既定値の変更の FutureWarning のテストが、位置引数のテスト以外は変更なしで通ることを確かめる
  - `flag_cbar` の非推奨の扱い（FutureWarning、`colorbar` との同時指定で `ValueError`）が v3.3.0 と同じであることを既存のテストで確かめる
  - _Requirements: 6.4, 8.1, 8.2, 8.3_

## 切り替えの段（v4.0.0）

- [ ] 5. 描画後の処理の切り替え
- [ ] 5.1 既定のレイアウト調整とカラーバーの自動追加を v4.0.0 の値にする
  - 決定表の未指定の行を変える: レイアウト調整が未指定でエンジンのない図は調整しない。カラーバーが未指定で三角図のカラーバーがすでにあるときは追加しない
  - 到達しなくなる「調整して警告」「追加して警告」の場合、警告のキー、文面の関数を消し、描画後の処理の入口から警告の分岐を消す（判定と入口を同時に変える統合の作業）
  - `tight_layout` の型と既定値（None）は変えず、None は調整しないことと同じ意味にする
  - 決定表のテストで、変えた 2 行と変えない行（True / False、エンジンあり、subfigure、mappable なし）を確かめる。結合テストで、引数を省略した三角図でエンジンのない図のレイアウトが変わらず警告も出ないこと、2 回目の値で色付けした描画でカラーバーが増えないこと、`tight_layout=True` と `colorbar=True` で v3.x と同じになることを確かめ、すべて通る
  - _Requirements: 3.1, 3.2, 3.3, 3.4, 4.1, 4.2, 4.3, 4.4, 8.3_

- [ ] 5.2 三角図のカラーバーが残っているかの判定を直す
  - 登録したカラーバーのうち、その Axes がまだ図に含まれているものが 1 本でもあれば「ある」と判定する。`remove()` の後に Axes の図が None になる版と、元の図のまま残る版の両方を正しく扱う
  - テストで、三角図が付けたカラーバーと同じ描画に matplotlib で別のカラーバーを足しても、続く既定の描画でカラーバーが増えないこと、`remove()` の後は増えること、2 本のうち 1 本を外しても「ある」になること、matplotlib で直接付けたものは数えないことを確かめ、すべて通る
  - _Requirements: 4.5, 5.1, 5.2, 5.3_

- [ ] 6. 公開メソッドの切り替え
- [ ] 6.1 オプションをキーワード専用にする
  - 4 つの公開メソッドでデータの後に `*` を置き、予告のデコレータと 1 回化のための private なメソッドを外す。予告の仕組みそのものは非推奨の汎用の手段として残す
  - 結合テストを v4.0.0 の挙動に書き換える: オプションを位置引数で渡すと `TypeError` になり何も描かない。キーワードとデータの位置引数は通り、v3.x と同じ意味で使われる。位置引数の予告の警告は出ない
  - 6 番目の位置引数の既存のテストを、`TypeError` を確かめるテストに書き換え、すべて通る
  - _Requirements: 2.1, 2.2, 2.3, 2.4_

- [ ] 6.2 `flag_cbar` を理由付きの `TypeError` にする
  - 削除した引数の文面（どのメソッドのどの引数が 4.0.0 で削除されたか、代わりに何を使うか）を作る関数を作る
  - `scatter` と `contour` に `flag_cbar` が渡されたら、描く前にその文面で `TypeError` を送出する
  - テストで、`TypeError` の文面に `flag_cbar` と `colorbar` が含まれ、Axes に何も足されていないことを確かめる。改名の予告を確かめていた既存のテストを書き換え、すべて通る
  - _Requirements: 6.3_

- [ ] 6.3 注釈の既定の整形を v4.0.0 の規則にする
  - `annotate` と `scatter` の注釈で `auto_latex_notation` が未指定なら、三角図の設定に従って化学式の形をした語だけを整形し、警告しない。mathtext（`$` を含む文字列）はそのまま表示する
  - 使われなくなる警告のキーと文面を消す
  - テストで、未指定のとき `"Sample 1"` はそのまま、`"Li2O"` は整形され、三角図の `auto_latex_notation=False` なら整形されず、警告が出ないこと、明示したときは従来どおりであることを確かめ、すべて通る
  - _Requirements: 6.1, 6.2_

- [ ] 6.4 縦横比の固定を `adjustable="box"` にする
  - 三角図の作成時の縦横比の固定方法を、Axes の枠を三角形に合わせて縮める方法に変える
  - テストで、既定が `box` であること、`layout="constrained"` でカラーバーの付く図で 3 つの頂点ラベルの描画範囲が図の範囲に収まること、作成後に `datalim` に戻した設定が描画とグリッドの描き直しの後も保たれることを確かめる。タスク 3 のテストを v4.0.0 の既定に合わせて書き換え、すべて通る
  - _Requirements: 7.1, 7.2, 7.3_

- [ ] 6.5 docstring を v4.0.0 の挙動に書き直す
  - 位置引数の予告の文を消し、`tight_layout`・`colorbar`・`auto_latex_notation` の項目に v4.0.0 の既定（未指定のときの挙動）を書く。クラスの docstring の縦横比の説明を `box` の方法にする
  - 共通の doctest のランナーと docstring の静的テストが、FutureWarning を出さずに通る
  - _Requirements: 9.5_

- [ ] 7. 切り替えの段の文書
- [ ] 7.1 CHANGELOG と移行ページを v4.0.0 の内容にする
  - CHANGELOG に破壊的変更の節を設け、既定値 3 つ、`flag_cbar` の削除、キーワード専用化、縦横比の固定方法、カラーバーの判定の修正を書く
  - 移行ページを「v4.0.0 で変わった」こととして書き直し、各変更について v3.x の挙動に戻す書き方（`tight_layout=True`、`colorbar=True`、`auto_latex_notation` の明示、作成後の `set_aspect` で `adjustable="datalim"`）を示す。FutureWarning の文面を見せていた捕捉のセルを、v4.0.0 の挙動に合わせて直す
  - ドキュメントのビルドが警告 0 件で通る
  - _Requirements: 9.3, 9.4_

- [ ] 7.2 使い方ページと README のリンクの説明を v4.0.0 の挙動にする
  - レイアウトとカラーバーのページ、はじめにのページ、ヒートマップと等高線のページの、v3.x / v4.0.0 の比較表と FutureWarning の説明を、v4.0.0 の挙動の説明に書き直す
  - README とトップページの移行ページへのリンクの説明を「v4.0.0 で変わった点」にする。最小の例のコードは変えず、README とトップページの一致のテストが通る
  - ドキュメントのビルドが警告 0 件で、使い方ページの実行で FutureWarning が出ない

  - matplotlib 3.10 と 3.11 の環境で、頂点ラベルが図の内側に収まるテストとカラーバーの判定のテストが通ることを確かめる
  - steering の tech.md と structure.md に、オプションはキーワード専用という規則と v4.0.0 の既定を反映する
  - _Requirements: 2.1, 3.1, 4.2, 5.1, 7.2, 8.3_
